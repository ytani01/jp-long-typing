## 問題の無かった観点

- NHK の RSS の形（`+0900`）: JS（`toIsoDate`）と Python（`parse_nhk`）のどちらでも同じ時刻になり、どの `TZ` でも `10/28 22:22`
- 一番新しいものを選ぶ処理: 並びが新しい順でなくても最大を取る（`20:53, …, 22:22:06, ''` → `22:22`）
- 年・日付の境目: `2026-12-31 15:00:00`（UTC）→ `1/1 00:00`、`14:59:59` → `12/31 23:59`。Python も `31 Dec 2026 15:00:00 +0000` → `2027-01-01T00:00:00+09:00`
- 日本以外のタイムゾーン: `+9 時間` してから `getUTC*` を読むので、ブラウザの `TZ` に左右されない（上の表の想定の形の行）
- 空・読めないとき: `''`・`null`・`undefined`・`'xx'` → `(1本)`、記事 0 件 → `(0本)`、全記事が読めない → `(2本)`。`Math.max()` が `-Infinity` になる場合も `Number.isFinite` で落ちる。例外は出ない（`toIsoDate` は `String()` で包み、`Date.parse` は例外を出さない）ので、取得全体が失敗扱いにはならない
- Python で読めないとき: `''`・`'xx'` は `ValueError` で `''` になる（3.14.8）。`TypeError` も拾っている
- `</` の置き換え: `dump` は変えておらず、`pubDate` の値にも効く（`a</script>` → `a<\/script>` を確かめた）
- `update-notes.sh` のメッセージ判定: `notes.py` の出す文言（`: 変更なし`、`: 最新 N 件に更新した`、`（NHK ニュース）: 取得できず更新しなかった`）は変わっていない
- `check`: まとめの行の文言（`NHK主要`・`本)`）に依っていない（`rg` で該当なし）
- 範囲: 指示に無い変更は無い
- コメント: 「なぜ」（日本時間にする理由、読めないときの扱い）を書いている
