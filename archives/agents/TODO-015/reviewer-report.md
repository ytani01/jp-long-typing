## 問題なしの観点

- 日本語の句読点を直前の日本語の字とまとめる: `"これは本。次"` → `こ|れ|は|[本。]|次`
- 英単語の後ろの句読点を単語に足す: `"ABC。次"` → `[ABC。]|次`、`"“Hi”。"` → `[“Hi”。]`
- 単語の中の ASCII 記号（`word` が開いているとき）は今までどおり単語に入る: `"Hello, world."` → `[Hello, ]|[world.]`、`"1,000円。"` → `[1,000]|[円。]`
- 単語の後ろの空白のあとの記号: `"Hello ."` → `[Hello .]`、`"ABC 」"` → `[ABC 」]`（空白は単語に付いたまま）
- 句読点の連続: `"た」。次"` → `[た」。]`、`"本当？！次"` → `本|[当？！]|次`（全角の `？！` は `isWordSide` が真だが、`word` が無いので新しい枝に入る）
- 改行の直後・文字列の先頭の句読点は、まとめる相手が無いので今までどおり 1 字で置く（`last` が `BR` / `null`）。`"本」\n次"` → `[本」]|⏎|<br>|次` で、`<br>` が `.word` に入ることは無い
- `.linebreak` の span は必ず直後に `<br>` が付くので、`last` が改行の span になることは無い
- 新しい枝のあとの `word = null` / `inLongWord = false` は、次の字で単語の判定（20 字超の数え直し）を正しくやり直す: `"本）ABC def"` → `[本）]|[ABC ]|[def]`
- `charElements` の順と `data-index`: 上の全 24 例で、DOM の並び・`charElements`・`data-index` が文字列の順と一致（`replaceChild` は同じ位置に置き換えるので順は崩れない）
- 規約: `index.html` 1 ファイル、外部ライブラリ無し。範囲外の変更無し（`TODO.md` はチェックを入れただけ）
- テスト: このリポジトリにテストの仕組みは無く、確認は verifier の Playwright。足りないとは言えない
