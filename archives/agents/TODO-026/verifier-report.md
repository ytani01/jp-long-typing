# TODO-026 確認報告（verifier）

対象: 未コミットの `index.html`。コードは変更していない。
手段: `archives/agents/TODO-026/verify.mjs`（node + Playwright、Chromium headless、1280x800）。
お手本は「自作テキスト」で `今日は晴れです。明日は雨です。`。各ケースは新しいブラウザ
コンテキストで始め直した。確定は `page.keyboard.insertText()` 1 回 = 確定 1 回。
確定後に 400ms 待ってから測った（色の transition 0.12s が終わってから）。

## 結果

実行: `node archives/agents/TODO-026/verify.mjs`、終了コード 0。ページ例外・console error は無し。

- ケース 1 `今日は晴れです。`: done 8、赤なし、ミス 0、入力欄は空。OK
- ケース 2 `今日わ晴れです。`: done 8、赤は「は」（rgb(248, 113, 113)）、ミス 1、入力欄は空。末尾まで進む。OK
- ケース 3 `今日晴れです。`: done 8、赤は「は」（rgb(248, 113, 113)）、ミス 1、入力欄は空。末尾まで進む。OK
- ケース 4 `今日はは` → `晴れです。`（2 回確定）: done 8、赤なし、ミス 1、入力欄は空。末尾まで進む。OK
- ケース 5 `今日わ`: done 2、赤なし、ミス 1、入力欄は空。次の字は「は」（active）。OK
- ケース 6（ケース 2 の続き、`明日は雨です。` を正しく打つ）: 結果モーダルが開いた。
  正確率 93%（`#res-accuracy`、画面の `#stat-accuracy` も 93%）、ミス打鍵 1、done 15 / 15。OK
  - 参考: 打鍵 15 字、正しく確定された字 14 字で 14/15 = 93.3%。`index.html` の式
    `Math.round(correctChars / totalAttempts * 100)` と一致する（`totalAttempts` は打鍵数と見て照合。コードの定義を読んだ上での推定）。

## 補足（判断は報告のみ）

- ケース 2 の正確率 88% は途中の値（7/8）。最終値は 93%。
- 最初の測定（400ms 待ちなし）では「は」の色が transition 途中の値（rgb(211, 119, 127) など）になった。
  待ちを入れて測り直した結果を上に載せている。実装の問題ではなく測り方の問題。
- 画面サイズ 1280x800、既定の制限時間は 30 秒。ケース中に時間切れは起きていない。
