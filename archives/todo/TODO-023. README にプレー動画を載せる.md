## きっかけ

README に、実際にプレーしている様子の動画を載せたい、と利用者から（2026-10-08）。
撮り方は Playwright で自動、載せ方は GitHub に添付した MP4、場面は
練習文の切り替え・打ち進める様子・結果画面・履歴と苦手の分析、と利用者が決めた。

## やったこと

- `tools/record-demo.mjs` を足した。`node tools/record-demo.mjs` で `tools/out/demo.mp4`
  （1280×800、約 48 秒、約 1 MB）を作る
  - 見本の履歴は、録画しないブラウザで `page.clock` を早送りしながら 5 回プレーして作り、
    `storageState` で録画するブラウザへ渡す。時計は 10 分前から始め、録画した回が
    いちばん新しくなるようにした
  - 打ち進める様子は、着手後に利用者が「ひらがな → 漢字に変換 → 確定 → 緑が進む」を
    見せたいと求めたので、DevTools Protocol の `Input.imeSetComposition` で読みを 1 字ずつ
    出し、変換した字に差し替えてから `Input.insertText` で確定する形にした。
    読みは辞書（kakasi・mecab）が無いので、『走れメロス』の冒頭 31 文節分を手で書いた
  - 「政治が」を「政事が」と変換し間違え、残った誤りを選んで一度に消して打ち直す場面を入れた。
    1 字ずつ Backspace で消すと、消すたびにミス打鍵として数えられるため
  - 履歴を開いたあと、一覧の最後までスクロールして 6 件を見せる
- `.gitignore` を作り、`tools/out/` を入れた（MP4 はコミットしない）
- MP4 を Chrome 拡張で GitHub の Issue 作成画面に添付して `user-attachments` の URL を得た
  （Issue は投稿していない）。README の冒頭にその URL と、変換は再現したものだという注記、
  撮り直しのコマンドを書いた
- CPM は、利用者が今のまま（約 130、ランク C 前後）でよいとした

## 分担の振り返り

- verifier は、履歴の一覧が欠けること、ミス打鍵の数え方、打ち直しの読みの誤り、日時の離れを
  見つけた。読みの誤りはスクリプトの不具合で、main のコマ割りの目視では拾えていなかった
- 見込みどおりの分担だったが、確認が 3 回に割れた。1 回目のあとに利用者が打ち方の変更を
  求めたためで、CLAUDE.md の「利用者の指示が固まるまで確認の担当を起こさない」に当たる。
  次は、main が撮った動画を利用者に先に見せてから verifier を起こす
- verifier にスクリプトを実行させると動画が撮り直され、利用者に見せたものと別物になる。
  最後の確認は既存の mp4 を見る形にした。次は、再現の確認（実行する）と、
  採用する動画の確認（実行しない）を分けて依頼する
