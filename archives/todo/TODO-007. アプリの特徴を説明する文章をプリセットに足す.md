## きっかけ

利用者の依頼（2026-10-07）。「日本語長文タイピング」の特徴を文章にしたお手本を足し、
選択欄の先頭に置いて、起動時の既定にする（Claude ニュースまとめから変える）。
README は箇条書き、お手本は文章にし、中身は README と食い違わないようにする。

## やったこと

- `index.html`: `PRESETS` の先頭に「日本語長文タイピングの特徴」を足した（段落は改行で区切る）。
  選択欄の先頭に「このアプリ」の optgroup を置き、既存のプリセットの value を 1〜6 に付け直した。
  起動時は `loadClaudeSummary()` の代わりに `loadArticle(PRESETS[0], '0')` で始める
- `README.md`: 「長文プリセット内蔵」に 1 行足し、「起動時の既定」をこの文章に書き換えた

「ニュース更新」を押したときに Claude ニュースまとめへ切り替える動きは変えていない。
裏の取得が終わったときにまとめへ差し替えるのは、まとめを開いたままのときだけなので、
起動時のお手本は上書きされない。

## 確かめたこと

verifier が README との突き合わせと Playwright での実測をした（`archives/agents/TODO-007/verifier-report.md`）。

- お手本の文章に、README と食い違う主張・README に無い主張は無い
- 起動 1.5 秒後に value=0、タイトルが「日本語長文タイピングの特徴」。先頭 10 字を入れて
  `currentIndex` 10、ミス 0。value=1・6 でそれぞれ「Claude Code 概要」「羅生門」。pageerror 0 件

## 分担の振り返り

- verifier は食い違いを見つけなかった。外部通信が成功したときに選択が上書きされないかを
  「未確認」として挙げたので、main がコードで確かめた（まとめを開いたままのときだけ差し替える）
- 見込みどおりの編成で、食い違いは無い
- 同じ規模（お手本の追加と既定の変更）なら同じ組み方でよい。外部通信の成功時の動きも
  確認の範囲に入れるなら、依頼に `page.route` で取得を成功させる条件を書く
