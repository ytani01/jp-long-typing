- reviewer と verifier は、Agent ツールでモデルと effort を見込みどおりに指定した

## きっかけ

利用者から「履歴から苦手な文字や単語を分析し、改善のアドバイスを作れるか」と聞かれた。
今の履歴は日時・題名・CPM・正確率・ランクだけで、今までの分は分析できない。
利用者と決めたこと: 範囲は記録と集計と、アプリの中の決まりで作るアドバイスの文まで。
苦手な語の練習文は作らない。Claude API は使わない（API キーと外部への送信が要るため）。

## やったこと

- `index.html`: 確定のたびに、確定した区間の時間を字数で割って字の種類（ひらがな・カタカナ・漢字・英数字・記号）ごとに足し、誤りはお手本の今の字と前後 3 字を残すようにした（`recordChunk`、`recordMiss`）
- `index.html`: 結果を保存するときに、字の種類ごとの記録、誤った字の上位 20 字、詰まった語（1 字あたりの時間がその回の平均の 2 倍を超えた 2 字以上の確定のうち遅い 3 つ）を足す（`statsForHistory`）。新しい 20 回より前の結果からは詳しい記録を落とし、履歴が大きくなりすぎないようにした
- `index.html`: 履歴の画面の表の上に、新しい 20 回分の集計（字の種類ごとの表、よく誤る字、詰まった語）とアドバイスの文を出す（`analyzeHistory`、`renderAnalysis`）。アドバイスは、誤り率・1 字あたりの時間が全体の 1.5 倍以上の種類、3 回以上誤った字、CPM の傾向（最近 5 回と前の 5 回）、最近の正確率から作る。1 字も打たなかった回は傾向から外す
- `README.md`: 保存する項目と分析の説明を足した

ローマ字の打ち間違いは IME の中で起きて拾えないので、分かるのは確定した字のどこで誤ったか・詰まったかまで。

## 確かめたこと

- reviewer: 要修正 1 件（CPM の傾向の文が不自然）、検討 8 件（前の回の CPM が 0 のときの `Infinity%`、何も打たない回が正確率の助言を押し上げる、履歴の大きさ、`・` がカタカナになる、記号の助言の文と照合の食い違い、README の保存項目、コメント、1 字あたりの時間の意味）をすべて直した（[reviewer-report.md](../agents/TODO-021/reviewer-report.md)）
- verifier: Playwright で、実際の練習で記録される値、何も打たずに時間切れにしたときに NaN が出ないこと、作った履歴から 4 つのアドバイスが出ること、21 件以上で古い件の詳しい記録が消えること、誤った字が 20 字までに絞られること、`charKind` の分類、pageerror 0 件を実測した。報告の 2 点を直したあと再確認した（[verifier-report.md](../agents/TODO-021/verifier-report.md)）

## 分担の振り返り

- reviewer は、0 除算と、何も打たない回が傾向を歪めることを node で実際に動かして見つけた。履歴の大きさの見積もり（1 件が約 9 倍）も reviewer の指摘で、main は考えていなかった。verifier は、前の回の CPM が 0 で文が不自然になる残りと、作った履歴で詰まった語が重複することを見つけた
- 見込みと食い違わなかった。ただ、verifier の指摘を直したあとの再確認が 1 回増えた
- 次に同じ規模（集計とその表示）なら同じ組み方にする。reviewer への依頼に「境界の値（0 回・0 字・同じ値の重複）を node で動かして見る」と最初から書くと、verifier の後の手戻りを reviewer の段階で拾える
